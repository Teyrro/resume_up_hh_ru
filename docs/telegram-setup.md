# Настройка Telegram-уведомлений (необязательно)

Сервис шлёт в Telegram: запуск, повторный вход на hh.ru, успешное поднятие резюме,
капчу и ошибки входа. Попытки, когда поднимать ещё рано, не отправляются.

Бот принимает команды только из чата `TG_CHAT_ID` (сообщения из других чатов
игнорируются):

| Команда | Действие |
|---|---|
| `/menu` | настройки кнопками: тихие часы (пресеты 23–08 / 22–09 / 00–08, «Своё время», «Выключить») |
| `/next` | когда следующее плановое поднятие, когда hh.ru его разрешит, итог последнего прохода |
| `/resume` | снять стоп-флаг и сразу запустить проход |
| `/help` | список команд и пояснение к каждому сообщению бота: что значит и что делать |

На любое другое сообщение, начинающееся с `/`, бот отвечает списком команд.
При запуске сервис регистрирует команды в меню Telegram (`setMyCommands`) — они
подсказываются при вводе `/`.

### Тихие часы

Время суток, когда резюме не поднимаются (например, ночью: люди в это время не
обновляют резюме, а рекрутеры не ищут). **По умолчанию выключены.**

- `/menu` → кнопка пресета (`23–08`, `22–09`, `00–08`) — включить сразу;
- «✏️ Своё время» → отправить сообщением `23-08` или `23:30-07:45`;
- «🚫 Выключить» — поднятия снова в любое время суток.

Запуск, выпавший на тихие часы, переносится на конец окна + случайно до 45 минут.
Настройка хранится в `data/settings.json` и переживает перезапуск; план пересчитывается
сразу, без лишнего прохода.

Когда нужен `/resume`, а когда сервис справится сам:

| Сообщение бота | Что делать |
|---|---|
| «hh.ru показал капчу…» | войти на hh.ru вручную в обычном браузере или подождать несколько часов, затем `/resume` |
| «3 ошибки входа подряд — сервис остановлен» | посмотреть `data/debug/` и логи, устранить причину, затем `/resume` |
| «Ошибка входа: …» | ничего — повтор через 1–2 часа |
| «Непредвиденная ошибка: …» | ничего — повтор через 30 мин и дальше реже |
| «Сессия слетела, но дневной лимит попыток входа исчерпан» | ничего — за сутки уже было `MAX_LOGINS_PER_DAY` входов по коду (по умолчанию 3); чтобы не вызвать капчу и не засыпать почту кодами, сервис ждёт до 9:00 следующего дня |
| «Сервис запущен», «Выполнен повторный вход…», «Поднято резюме: N» | ничего, информационные |
Команды, отправленные, пока сервис был выключен, при запуске пропускаются.

> Бот можно опрашивать только из одного места. Если сервис запущен в двух местах
> с одним токеном (например, локально и на сервере), Telegram вернёт `409 Conflict`
> и команды будут работать нестабильно — оставьте один экземпляр.

Если `TG_BOT_TOKEN` или `TG_CHAT_ID` пустые — уведомления выключены, сервис работает.

## 1. Создать бота — `TG_BOT_TOKEN`

1. Открыть [@BotFather](https://t.me/BotFather), отправить `/newbot`.
2. Задать имя и username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AAH...` — это `TG_BOT_TOKEN`.

Документация: https://core.telegram.org/bots/tutorial#obtain-your-bot-token

## 2. Узнать chat_id — `TG_CHAT_ID`

1. Найти своего бота в Telegram, нажать **Start** и написать ему любое сообщение.
   Без этого бот не может писать вам первым.
2. Выполнить (вместо `<TOKEN>` — токен):

   ```bash
   curl -s "https://api.telegram.org/bot<TOKEN>/getUpdates" | grep -o '"chat":{"id":-\?[0-9]*' | head -n 1
   ```

3. Число после `"id":` — это `TG_CHAT_ID`.

Если ответ пустой (`"result":[]`) — боту ещё не писали, отправьте сообщение и повторите.

## 3. Заполнить `.env`

```
TG_BOT_TOKEN=123456789:AAH...
TG_CHAT_ID=123456789
```

Проверка: `docker compose run --rm hh-autoraise check` — в чат придёт
«hh-autoraise: Проверка связи: Telegram работает.»
